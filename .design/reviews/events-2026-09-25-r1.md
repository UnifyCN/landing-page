## Needs decision

**N-1. Sidebar position below 1100px.** `DESIGN.md` → "Responsive and accessibility": "Sidebar stacks **below** the list under the desktop-content breakpoint." The approved mockup (`b-agenda.html`, `@media (max-width: 1100px) .aside { order: -1 }`) and the build (`EventsAgenda.astro:739-741`) put it **above** the list. Measured cost on phones: first event at 2.02 screens (390) and 2.73 screens (320). Options: (a) follow the contract: sidebar below the list; (b) keep it above but collapse the calendar to a one-line "Pick a date" disclosure on ≤700px; (c) keep as built and amend the contract. Record the choice as D-004 in `.design/decisions.md`. Whatever is chosen, make DOM order match visual order (P1-7).

## Prioritized fixes

### P0 (clears the gate)

1. **`src/styles/global.css` → `--color-events-faint`**: change `#8a8784` to `#6b6763` (5.61:1 on white, 5.07:1 on `--color-events-warm`, 4.87:1 on `--color-events-red-wash`). This one change fixes all 11 usages: `EventCard.astro:284`; `EventsAgenda.astro:333, 370, 402, 448, 590, 653, 710`; `[event].astro:411, 470, 562`. Check that `.ag-chip.is-dim` still reads as dimmed (the dashed border carries that cue).
2. **`src/components/events/EventsHero.astro` → hero eyebrow on narrow and very wide screens**: the copy spans the full width at ≤700px, so the 90° scrim is only 0.28–0.62 under it. Either add `@media (max-width: 700px) { .evh::before { … } }` with a flatter left-to-right gradient (for example 0.8 → 0.6), or strengthen the top stop of the 180° gradient under the eyebrow row. Target: eyebrow ≥4.5:1 per glyph at 320/390/1920 (re-run `_review-hero.mjs`). The H1 minimum at 320 is 2.75:1 (p5 3.33) at the right edge over the projector screen; the same scrim change lifts it above 3:1.
3. **Stats (HOLD, already decided)**: confirm or remove before production (`EventsHero.astro:15-20`).

### P1 (should fix before ship)

4. **`src/pages/events/[event].astro:228-230` + `EventCard.astro:87-89`**: the "More from" list uses the row variant, which hides the date visually. Add a visible date for rows outside the agenda (for example a `showDate` prop that renders `{dateLabel} · {timeLabel}` like the feature variant).
5. **`EventsAgenda.astro:907-910`** month-nav focus: `el?.focus() ?? fallback` always runs the fallback because `focus()` returns `undefined`. Query the same-direction button first, then focus it, and fall back only when it is `null`. Today, Enter on "Next month" lands on "Previous month".
6. **`EventsAgenda.astro:922-931`** "Show more" focus: `firstHidden` counts items that are hidden by filters. Capture `const firstNew = matches[oldLimit]` (the first match past the old limit) before `limit += pageSize`, then focus its link. Verified bug with `?partner=sfu`.
7. **`EventsAgenda.astro:100-259`** DOM vs visual order below 1100px: after N-1, place `<aside>` before `.ag-main` in DOM when it shows first (use `grid-column` on desktop to keep it right), or keep DOM as is if the sidebar moves below the list.
8. **Touch targets** (`EventsAgenda.astro:342-344, 561-565`): `.ag-cal-nav` 2.25rem → 2.75rem; `.ag-chip` `min-height` → 2.75rem at ≤700px. `Navbar.astro:371-377` `.nav-caret` 1.25rem → at least 1.5rem (24px).
9. **Calendar keyboard** (`EventsAgenda.astro:208, 936-948`): meet the contract ("real grid … arrows move days"): roving `tabindex` (one Tab stop per month), ArrowLeft/Right = previous/next event day, ArrowUp/Down = same weekday ±7 (or the nearest event day), cross into the adjacent month at the ends, Home/End. Or relax the contract text to match the current behaviour.

### P2 (improvements)

10. **`EventCard.astro:19`** give the card link a short name: `aria-labelledby` pointing at the title plus a visually hidden "date, time, host" span; keep badges and location out of the name.
11. **Heading levels**: pass a `headingLevel` prop to `EventCard` so agenda cards are `h4` under the `h3` group heading (featured and "More from" can stay `h3`).
12. **`EventsAgenda.astro:894-896`**: use `behavior: matchMedia("(prefers-reduced-motion: reduce)").matches ? "auto" : "smooth"`.
13. **`EventsAgenda.astro:603`**: tokenise `#c4bfb9` (for example `--color-events-day-idle`) and darken it for legibility; tokenise the 6/9/10/12px radii or map them to existing radius tokens.
14. **No-cover placeholder** (`EventCard.astro:153-167`): at 232px wide the blank warm panel with a 44px faint mark reads as a broken image. Use the partner logo (already in `partners.ts`) or a genre word-mark at a larger size.
15. **Chips vs `/resources`**: either align `.ag-chip` with `.rv-filter-btn` (filled neutral, as the contract says "reuse"), or amend `DESIGN.md` to say the outlined chip is the new shared pattern and plan to move `/resources` and `/blog` to it.
